# SiteWatch

Telegram-бот на Python 3.11+ для круглосуточного мониторинга сайтов, API-эндпоинтов и TLS/SSL-сертификатов. Бот измеряет время от начала GET-запроса до получения заголовков конечного ответа. После перенаправлений коды 200–399 означают доступность, остальные коды и ошибки соединения — недоступность.

- Меню, карточки и формы обновляются в одном сообщении бота. Если Telegram не разрешает редактирование, бот отправляет новое сообщение. Ручные проверки показывают короткое всплывающее уведомление и обновляют результат в том же окне. Превью ссылок отключены.
- Добавление состоит из двух шагов: короткое название проекта, затем полный URL. Экран первой проверки превращается в карточку монитора. Эта проверка учитывается в серии. До подтверждения сбоя карточка показывает последний подтверждённый статус, свежие показатели и число ошибок подряд.
- Бот сообщает о сбое активного монитора после `FAIL_THRESHOLD` неудачных проверок подряд. Первый успешный ответ сбрасывает счётчик и вызывает уведомление о восстановлении, если сбой был подтверждён. Ручные и фоновые проверки учитываются в одной серии. Для HTTPS он отдельно проверяет сертификат исходного хоста и предупреждает, когда до истечения остаётся до 7 полных дней включительно. После обнаружения сертификата с остатком более 7 дней предупреждение снова доступно.
- В меню можно проверить один сайт или все сайты сразу, приостановить мониторинг, удалить сайт или изменить интервал отдельного монитора. Ручная проверка работает и на паузе.
- Кнопка «История сбоев» в карточке показывает до 10 последних подтверждённых сбоев и восстановлений с временем UTC и деталями проверки. Ручные проверки на паузе попадают в историю при смене подтверждённого статуса. Уведомления на паузе отключены. При удалении монитора удаляется его история.
- Мониторы, счётчики и история хранятся в SQLite. При запуске схема существующей базы обновляется автоматически. Незавершённый ввод в диалогах сбрасывается при перезапуске.

## Установка и запуск

1. Создайте бота через @BotFather в Telegram и получите токен.
2. Из каталога проекта установите зависимости:

   ```text
   python -m venv .venv
   ```

   Для активации окружения в PowerShell используйте `.venv\Scripts\Activate.ps1`, в POSIX-совместимой оболочке — `source .venv/bin/activate`.

   Установите зависимости интерпретатором созданного окружения:

   ```text
   pip install -r requirements.txt
   ```

3. Создайте рядом с `main.py` файл `.env`, скопируйте в него содержимое `.env.example` и заполните `BOT_TOKEN`. Для приватного бота укажите свой числовой Telegram ID в `ADMIN_IDS`.
4. Запустите бота:

   ```text
   python main.py
   ```

5. Откройте личный чат с ботом, отправьте `/start` и нажмите «Добавить сайт». Команда `/help` открывает справку, `/cancel` отменяет текущий ввод.

Для круглосуточной работы держите один экземпляр `python main.py` запущенным на постоянно работающем компьютере или сервере. Для фоновых проверок и Telegram требуется доступ в интернет. GET-проверки доступны для публичных адресов. Перед подключением бот проверяет все IP-адреса, возвращённые DNS. Если хотя бы один адрес непубличный, проверка возвращает «Локальные и приватные адреса запрещены». Это правило применяется и к перенаправлениям. Если сертификат недоступен или проверка доверия TLS завершается ошибкой, остаток дней отображается как «—».

## Настройки `.env`

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Обязательный токен Telegram-бота |
| `ADMIN_IDS` | пусто | Разрешённые числовые Telegram ID через запятую. Пустой список открывает доступ всем пользователям в личном чате |
| `CHECK_INTERVAL` | `60` | Интервал фоновой проверки в секундах. В карточке сайта можно задать свой интервал или ввести `0` для возврата к общему |
| `FAIL_THRESHOLD` | `2` | Число последовательных неудачных проверок для подтверждения сбоя. Значение `1` включает уведомление при первом сбое |
| `REQUEST_TIMEOUT` | `10` | Таймаут HTTP и отдельной TLS-проверки в секундах |
| `MAX_SITES_PER_USER` | `20` | Максимальное число мониторов у одного пользователя, включая паузу |
| `DB_PATH` | `sitewatch.db` | Путь к SQLite. Для вложенного пути заранее создайте родительский каталог |

`.env` и стандартный файл SQLite исключены из Git. При выборе другого расширения для базы храните файл в отдельном каталоге вне репозитория.
